# 2026-VK-EDU-Web-12-Goloshchapov-R

Учебный проект курса VK Education Web.

- **ДЗ1** — статическая верстка сайта вопросов и ответов (AskRoman) без бэкенда: папка `public/`.
- **ДЗ2** — тот же сайт на Django: views, маршрутизация, шаблонизация, пагинация, окружение для запуска (venv и Docker).
- **ДЗ3** — модели базы данных, Django Admin, генерация тестовых данных и отображение вопросов и ответов из базы данных.

## Запуск проекта (ДЗ2–ДЗ3, Django)

Для этого способа нужны Docker и Docker Compose. Локально устанавливать Python и PostgreSQL не требуется.

1. Создай файл `.env.docker` на основе примера:

   ```bash
   cp .env.example .env.docker
   ```

2. Запусти контейнеры:

   ```bash
   docker compose up --build
   ```

   Docker Compose запустит PostgreSQL, дождётся его готовности, выполнит миграции Django и запустит сервер. Для Django адрес базы данных внутри Docker-сети — `db`, он задаётся в `docker-compose.yml`.

3. Открой http://127.0.0.1:8000/.

Для остановки контейнеров нажми `Ctrl+C`, затем выполни:

```bash
docker compose down
```

Для остановки контейнеров с удалением данных PostgreSQL и загруженных файлов:

```bash
docker compose down -v
```

Команда с `-v` удаляет тома, поэтому данные базы и файлы из `media/` будут потеряны.

Код проекта смонтирован в контейнер как volume — изменения файлов на хосте сразу видны внутри контейнера. Данные PostgreSQL и загруженные файлы хранятся в отдельных именованных томах.

## Переменные окружения

Все переменные перечислены в `.env.example`.

| Переменная | Назначение |
|---|---|
| `DJANGO_SECRET_KEY` | Секретный ключ Django |
| `DJANGO_DEBUG` | Режим отладки (`True`/`False`) |
| `DJANGO_ALLOWED_HOSTS` | Список разрешённых хостов через запятую |
| `DB_ENGINE` | Backend базы данных Django |
| `DB_NAME` | Имя базы данных |
| `DB_USER` | Пользователь базы данных |
| `DB_PASSWORD` | Пароль пользователя базы данных |
| `DB_HOST` | Адрес базы данных: `localhost` локально, `db` в Docker |
| `DB_PORT` | Порт базы данных |
| `POSTGRES_DB` | Имя базы данных в контейнере PostgreSQL |
| `POSTGRES_USER` | Пользователь PostgreSQL в Docker |
| `POSTGRES_PASSWORD` | Пароль пользователя PostgreSQL в Docker |

`.env.local` используется для локального запуска, `.env.docker` — для Docker Compose. Эти файлы не коммитятся в Git. В репозитории хранится `.env.example` без реальных секретов.

## Страницы и маршруты (Django, ДЗ2–ДЗ3)

| URL | Шаблон | Описание |
|---|---|---|
| `/` | `questions/index.html` | Список новых вопросов |
| `/hot/` | `questions/hot.html` | Список популярных вопросов |
| `/tag/<tag_name>/` | `questions/tag.html` | Список вопросов по тегу |
| `/question/<id>/` | `questions/question.html` | Страница одного вопроса со списком ответов |
| `/ask/` | `questions/ask.html` | Форма добавления вопроса |
| `/login/` | `core/login.html` | Форма входа |
| `/signup/` | `core/signup.html` | Форма регистрации |
| `/profile/` | `core/profile.html` | Форма редактирования профиля |

Списки новых и популярных вопросов, вопросы по тегу и отдельный вопрос получают данные из базы данных. Для отсутствующих объектов возвращается 404. Для пустой базы предусмотрены сообщения об отсутствии вопросов и ответов.

## Наполнение тестовыми данными (ДЗ3)

Для генерации тестовых данных используется Django management command:

```bash
python manage.py fill_db [ratio]
```

Параметр `ratio` задаёт количество записей:

- пользователей — `ratio`;
- вопросов — `ratio * 10`;
- ответов — `ratio * 100`;
- тегов — `ratio`;
- оценок — `ratio * 200`.

Для небольшой проверки можно выполнить:

```bash
python manage.py fill_db 10
```

Для объёма данных из задания:

```bash
python manage.py fill_db 10000
```

Для генерации используется Faker. Записи создаются пакетами через `bulk_create`, без отдельного `save()` для каждой записи. Команда рассчитана на запуск на пустой базе. Повторно запустить её с тем же `ratio` нельзя, если соответствующие тестовые пользователи или теги уже существуют.

### Административная панель

Создай суперпользователя:

```bash
python manage.py createsuperuser
```

В Docker это можно сделать отдельной командой:

```bash
docker compose exec web python manage.py createsuperuser
```

После запуска сервера административная панель доступна по адресу http://127.0.0.1:8000/admin/.

В админке доступны пользователи, профили, вопросы, ответы, теги и оценки. На странице пользователя отображается Inline профиля, на странице вопроса — Inline ответов.

## Статическая верстка (ДЗ1)

Чистые HTML-файлы без шаблонизатора находятся в папке `public/`. Их можно открывать напрямую в браузере, например `public/index.html`. Для просмотра статической верстки запуск Django и базы данных не требуется.

## Структура проекта

```text
AskRoman/              — настройки Django-проекта (settings.py, urls.py)
core/                  — приложение: вход, регистрация, профиль
questions/             — приложение: вопросы, ответы, пагинация
static/                — исходная статика (css/js/img)
staticfiles/           — результат collectstatic
media/                 — загруженные пользователями файлы
public/                — статическая верстка ДЗ1
requirements.txt       — зависимости Python
.env.example           — пример переменных окружения
Dockerfile             — образ для запуска Django-приложения
docker-compose.yml     — запуск Django и PostgreSQL через Docker Compose
```
